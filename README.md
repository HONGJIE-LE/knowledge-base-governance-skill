# Knowledge Base Governance Skill

面向本地知识库的通用治理 Skill，适用于支持 `SKILL.md` 或同等技能机制的 AI 工具。

## 两个独立模块

### 模块一：通用知识库检查

- 先识别知识库实际板块可能承担的功能，再检查问题。
- 不强制采用 Raw、Wiki、Projects、Outputs 或任何固定目录和属性。
- 使用真实目录名和文件名报告，并区分已确认结论与候选映射。
- 默认只读，不自动移动、删除、改名或修改配置。

### 模块二：知识库六维健康度诊断

- 按 D1-D6 共 100 分诊断知识库成熟度。
- 输出阶段、降级触发器、关键证据、改进动作和三周复测目标。
- 先识别各知识库中功能等价的板块，再按统一评分口径诊断。

## 通用性原则

- 不绑定特定 AI 工具、知识库应用或工作仓库。
- 应用配置目录只作为兼容扫描线索，不定义 Skill 身份。
- 目录名不同不扣分，功能缺失、定位混乱或无法调用才构成问题。
- 扫描器结果只是候选线索，必须去重、抽样核验并标注证据状态。

## 安装

1. 下载 Release 中的 `knowledge-base-governance-v2.0.0.zip`。
2. 解压后取得 `knowledge-base-governance` 文件夹。
3. 将整个文件夹复制到当前工具支持的 Skills 目录。
4. 重新载入 Skills。

安装后的核心文件：

```text
knowledge-base-governance/
├── SKILL.md
├── references/
├── scripts/
└── test-prompts.json
```

## 使用示例

```text
检查一下这个知识库，告诉我最影响使用的三个问题。
```

```text
对这个知识库做一次六维健康度诊断。
```

```text
检查知识库的属性、查询、扩展、同步和备份设置。
```

## 运行条件

- Bash
- `find`、`grep`、`awk`、`sed`、`sort`、`wc`、`stat`、`date` 等系统基础命令
- 不要求安装 ripgrep（`rg`）
- `git`、`jq` 和知识库应用控制接口均为可选能力
- 缺少应用控制能力时，只完成文件层检查，不声称验证运行效果

## 安全边界

- 扫描脚本默认只读。
- 不读取或展示凭证值。
- 不因检查而自动修改、移动或删除知识库文件。
- 高影响写入、改配置、安装扩展或处理重复文件前，必须提供文件级预览并获得确认。

## 从旧版迁移

`v2.0.0` 使用新的通用 Skill 标识。安装新版后，应停用旧版，避免两个版本重复触发。
